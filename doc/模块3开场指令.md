## 必须做到
1. **引入 Redis**：加 `spring-boot-starter-data-redis` + Lettuce，在 `application.properties` 配置 host/port（开发用本地 Redis，默认 `localhost:6379`）；并在回复里给出「本机需先启动 Redis」的启动说明。
2. **Lua 脚本放 `resources/lua/`**，且「检查 + 扣减 / 释放」必须在**同一个脚本内**完成：
   - `occupy.lua`：先遍历 KEYS 判 `cur >= need`，再统一 `DECRBY`；全过返回 1，否则 0。
   - `release.lua`：遍历 KEYS 统一 `INCRBY`。
   - **两步拆开即竞态，违反打回。**
3. **关键类 `RedisInventoryService`**：
   - `initSlot(storeId, carTypeId, date, n)` → `SET key n NX`（不存在才设，初始值来自模块2 `availableCount` 的 N）
   - `getAvailable(storeId, carTypeId, LocalDate date)` → GET 单日剩余
   - `occupy(storeId, carTypeId, start, end)` → 展开日期 → 调 `occupy.lua` → 返回布尔
   - `release(storeId, carTypeId, start, end)` → 调 `release.lua`
   - `rebuildFromDb(storeId, carTypeId)` → 从 `order` 聚合真实占用重算剩余（Redis 丢失/初始化兜底）
4. **库存模型**：Key = `inv:{storeId}:{carTypeId}:{date}`，值 = 当天剩余可用辆数；**跨天预约必须展开为多个 date 槽**。
5. **选车接口** `POST /carType/available` {city, storeId, carTypeId?, start, end, priceMin?, priceMax?} → 用 `getAvailable` 过滤已满日期段，返回该时段仍可用的车型列表（RENTER 可查）。

## 复用与红线
- 复用模块1/2 已有资产（Result / CustomException / GlobalExceptionHandler / UserContext / JwtUtil / 拦截器），**禁止为同功能重写**。

## 自测（必须做，且逐条回报证据）
- `occupy.lua` 检查与扣减合一；用**并发双占**（两线程 / 两次紧贴调用，inv 初值=1）验证只有一个成功、另一个被拒。
- 选车接口正确过滤已满日期段（造数据：某日期 `inv=0` → 该日期不出现在结果列表）。
- `rebuildFromDb` 能从 DB 重算剩余（手动改 `order` 占用后调用，对比 `getAvailable` 值一致）。
- `release` 可把占用还回（`occupy` → `release` → `getAvailable` 恢复）。
